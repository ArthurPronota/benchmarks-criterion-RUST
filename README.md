# benchmarks с criterion в RUST

Rust-проект, демонстрирующий микробенчмаркинг с библиотекой Criterion.

### Назначение

Измеряется производительность функции, которая вычисляет сумму чисел от `1` до `n`:

```10:10:C:\Users\user\Job\Rust\CookBookProjects\o_089\benches\sum_bench.rs
fn sum_to(n: u64) -> u64 { (1..=n).sum() }
```

Бенчмарк многократно вызывает её для `n = 1000`:

```12:20:C:\Users\user\Job\Rust\CookBookProjects\o_089\benches\sum_bench.rs
fn bench(c: &mut Criterion) {
 c.bench_function(
    "sum_to_1000", 
    |b| 
        b.iter(|| sum_to(black_box(1000))
    ));
}
```

`black_box(1000)` мешает компилятору полностью заменить вызов заранее вычисленной константой. Однако оптимизатор всё ещё может преобразовать суммирование диапазона в очень эффективную арифметическую операцию.

### Структура

- `Cargo.toml` — пакет `o_089`, Rust edition 2024, зависимость Criterion 0.8.2.
- `src/main.rs` — стандартная программа `Hello, world!`; в работе бенчмарка практически не участвует.
- `benches/sum_bench.rs` — реализация функции и регистрация бенчмарка.
- `target/criterion/` — сформированные Criterion отчёты, статистика и графики.
- `.gitignore` — исключает каталог `target`.

Для Criterion отключён стандартный тестовый harness:

```8:9:C:\Users\user\Job\Rust\CookBookProjects\o_089\Cargo.toml
[[bench]]
name = "sum_bench"
harness = false
```

### Полученный результат

Сохранённый запуск показывает время около **0,75 нс** на операцию и отсутствие статистически значимого изменения производительности относительно предыдущего запуска:

- интервал: примерно 746–758 пс;
- изменение: около +0,35%;
- `p = 0,55`, поэтому изменение считается шумом;
- найдено 4 выброса из 100 измерений.

Запуск выполняется командой:

```powershell
cargo bench
```

В целом это минимальный пример настройки Criterion, применения `black_box` и анализа статистических результатов микробенчмарка.
